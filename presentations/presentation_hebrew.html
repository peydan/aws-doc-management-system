פלטפורמת ניהול מסמכים מבוססת ענן (Cloud-Native)

ארכיטקטורת Serverless מנותקת לניהול תוכן ארגוני, אי-הפיכות (Immutability) וממשל מטא-דאטה

תרשים 1.0: ארכיטקטורת פתרון Serverless מלאה ב-AWS 🔍 לחץ להגדלה

מודל 5 רמות הסמכות והעקביות (Authority Model)

מבטל את הצורך בטרנזקציות מבוזרות (2PC) על ידי הגדרת גבולות סמכות חדים לשירותי AWS ייעודיים:

1. סמכות התוכן הבינארי Amazon S3

אחסון בינארי בלתי ניתן לשינוי (PDF, TIFF, תמונות, מסמכי Office). אובייקטים מנוהלי גרסאות עם מדיניות WORM מחמירה החוסמת מחיקת גרסאות (s3:DeleteObjectVersion DENY).

2. סמכות המטא-דאטה Amazon S3 Object Annotations

מטא-דאטה JSON מלא ומבני הנשמר כאנוטציות אובייקט ייעודיות (document-metadata) הצמודות ישירות לגרסת ה-S3. תואם באופן מלא לתקן JSON Schema Draft-07.

3. שכבת הבקרה והמצביעים Amazon DynamoDB

טבלה יחידה (Single-Table Design) המנהלת מצביעי גרסה פעילה, היסטוריית גרסאות, נעילות אופטימיות (OCC) וסשנים של העלאה בזמני תגובה של פחות מ-10 מילישניות.

4. היטל שאילתות וחיפוש OpenSearch Serverless

היטל קריאה נגזר לחלוטין המוזן אסינכרונית דרך DynamoDB Streams ו-SQS. במקרה של השבתת אינדקס החיפוש, פעולות קליטה, עריכה והורדה נותרות זמינות ב-100%.

5. תיעוד ביקורת בלתי מחיק S3 Audit Bucket

תיעוד שינויים (CDC) הנכתב אוטומטית לקובצי JSON חתומים ומוצפני KMS במבנה מחולק לפי תאריכים לצרכי רגולציה וחקירה פורנזית.

ארכיטקטורת Serverless מלאה ומנוע חישוב AWS Lambda

אפס ניהול שרתים, גמישות אלסטית מיידית ומיקרו-פרימטרים של הרשאות מינימליות (Least Privilege)

תשתית מחשוב ו-Serverless
הרצה מונחית אירועים (Event-Driven)
כלל רכיבי המחשוב הם 100% חסרי מצב (Stateless) ומגיבים לאירועים: בקשות HTTP REST, אירועי CDC ב-DynamoDB Streams, או תורי משימות SQS — עם Scale to Zero במצב סרק.
• תשלום מדויק לפי מילישניות ריצה בלבד
• שרידות וזמינות גבוהה אוטומטית ב-Multi-AZ
אבטחת מיקרו-פרימטר (IAM Scope)
לכל פונקציית Lambda תפקיד IAM Execution Role ייעודי עם הרשאות מוגבלות בקפידה (למשל, פונקציית השאילתות מחזיקה בהרשאות קריאה בלבד ללא שום הרשאת כתיבה ל-S3/DynamoDB).
• מניעה מוחלטת של הסלמת הרשאות חוצת-פונקציות
• אפס משטח תקיפה של מערכות הפעלה או SSH
ביצועים ושרידות בתת-שנייה
חבילות קוד TypeScript קלות על גבי Node.js 20.x ו-AWS SDK v3 מבצעות קימפול סכמות בזיכרון בזמן Cold Start, ומאפשרות ולידציה וביצוע בפחות ממילישנייה בבקשות חמות.
• Cold Starts מותאמים לפחות מ-250ms
• אימות סכמות JSON בזיכרון ללא פניות לרשת

טופולוגיית פונקציות ה-Lambda ואחריות תפעולית

שם פונקציית ה-Lambda סוג טריגר / תפקיד תחומי אחריות עיקריים זמן ריצה מקסימלי וזיכרון הרשאות IAM מוגדרות
UploadInlineFunction Sync REST / Command קליטת קבצים עד 4MB, חישוב SHA-256, כתיבת קובץ + אנוטציה ל-S3, וביצוע טרנזקציית DynamoDB אטומית. 10s / 512 MB S3 PutObject, DynamoDB TransactWrite
UploadDirectInit / Complete Sync REST / Command הנפקת כתובות Presigned PUT ל-15 דקות לקבצים גדולים; אימות סיום העלאה ב-S3 ויצירת רשומות קטלוג. 10s / 256 MB S3 Presign & HeadObject, DynamoDB Write
MetadataUpdateFunction Sync REST / Command אכיפת נעילה אופטימית (OCC) עם expected_metadata_revision, אימות Ajv, כתיבת אנוטציה ועדכון מצביע. 10s / 256 MB S3 Get/PutObject, DynamoDB ConditionalUpdate
GetDocument / Version / Download Sync REST / Query קריאת מצביע וגרסאות מ-DynamoDB, שליפת מטא-דאטה מוסמך מ-S3, והנפקת כתובות הורדה מאובטחות (Presigned GET). 10s / 256 MB DynamoDB Strongly Consistent Read, S3 Presign
SearchDocumentsFunction Sync REST / Search תרגום מסננים ל-OpenSearch DSL; ביצוע שאילתות חתומות IAM SigV4 עם דפדוף סמן (Cursor Pagination). 15s / 512 MB aoss:APIAccessAll on Collection
StreamProcessorFunction Async / DynamoDB Stream האזנה לאירועי CDC, כתיבת תיעוד ביקורת JSON מחולק לפי תאריך ל-S3 Audit, ושליחת משימות אינדוקס ל-SQS. 30s / 256 MB DynamoDB Streams, S3 Audit Put, SQS Send
IndexerConsumerFunction Async / SQS Queue עיבוד מקבצי הודעות SQS, שליפת אנוטציית S3 ועדכון/מחיקה ב-OpenSearch. ניתוב הודעות תקולות ל-DLQ. 60s / 512 MB SQS Receive/Delete, S3 Get, AOSS Upsert

ניהול גרסאות מסמכים בלתי ניתנות לשינוי ו-S3 Annotations

פתרון מלא למגבלת 2KB במטא-דאטה של S3 באמצעות פיצ'ר Amazon S3 Object Annotations

ארכיטקטורת אחסון וגרסאות
פיצ'ר ה-Native AWS Amazon S3 Object Annotations
המערכת משתמשת ב-API של S3 Object Annotations (באמצעות PutObjectAnnotationCommand ו-GetObjectAnnotationCommand), המאפשר הצמדת מטא-דאטה עשיר ומבני (עד 1MB) ישירות לגרסת האובייקט ללא ריבוי קובצי Sidecar.
Native S3 Binding:
s3://{bucket}/documents/{class}/{doc_id}   (Versioned Binary)
  └── Annotation Name: document-metadata   (JSON Metadata Payload)
  • אפס פיצול קבצים (Zero Sprawl): המטא-דאטה קשור ישירות לגרסת הקובץ ב-S3 ללא צורך בקובץ נוסף נפרד.
  • מחזור חיים מנותק: עריכת מטא-דאטה מעדכנת את האנוטציה במקומה (In-Place) ללא שכפול הקובץ הבינארי או יצירת גרסת קובץ מיותרת.
  • מוכנות לאנליטיקת Iceberg: תמיכה מובנית בקטלוג אנוטציות ישירות לטבלאות Apache Iceberg עבור שאילתות SQL ו-BI ארגוני.
מודל מעקב גרסאות תלת-שכבתי (Version Lineage)
כל מסמך מתחזק 3 מונים נפרדים להבטחת עקביות מוחלטת בין הקובץ הבינארי, המטא-דאטה ושכבת האחסון:
1. גרסת אפליקציה (application_version: 1, 2, 3...):
מספר שלם עולה. מקודם אך ורק בעת העלאת קובץ בינארי חדש דרך POST /documents/{id}/versions.
2. מזהה גרסת S3 (s3_version_id: "3/L4bqt..."):
מזהה גרסה ייחודי ובלתי ניתן לשינוי המונפק על ידי S3 ומייצג את הבתים הפיזיים המאוחסנים באחסון.
3. רוויזיית מטא-דאטה (metadata_revision: 1, 2, 3...):
מונה OCC עולה. מקודם בכל קריאת PATCH /metadata ומאופס ל-1 בעת יצירת גרסת קובץ חדשה.

מטריצת מוטביליות של שדות מטא-דאטה (סכמה: bank.document-metadata/1)

שמות השדות קטגוריה כלל מוטביליות (Mutability) מנגנון עדכון ובקרה
document_id, document_class, created_at, created_by זהות מערכת Strictly Immutable נוצר פעם אחת ביצירת המסמך. ניסיון עריכה ב-PATCH נדחה מיד.
application_version, content_type, content_length, content_checksum מפרט בינארי Immutable for Version קשור קריפטוגרפית לקובץ (SHA-256). מתעדכן אך ורק בהעלאת גרסת קובץ חדשה.
metadata_revision, metadata_updated_at, metadata_updated_by בקרת מקביליות System Monotonic מנוהל ומקודם אוטומטית על ידי ה-Lambda ונעילות DynamoDB OCC.
customer_id, complete_customer_id_code, account_id, business_area_code, loan_number, currency... שדות עסקיים ומשותפים Mutable via PATCH ניתן לעריכה באמצעות PATCH /metadata בכפוף לנעילה אופטימית וסכמת JSON.

הפרדת אחסון ו-CQRS: Amazon DynamoDB מול OpenSearch Serverless

ארכיטקטורת CQRS המפרידה בין שכבת בקרה טרנזקציונית מהירה להיטל חיפוש אלסטי

ארכיטקטורת נתונים ו-CQRS

Amazon DynamoDB (Single-Table)

OLTP / Source of Truth

מהווה את עמוד השדרה הטרנזקציוני המהיר, מתאם הנעילות האופטימיות וסמכות המצביעים הפעילים.

Primary Key Patterns:
• Document Pointer: pk: DOC#{id} | sk: DOC
• Version History: pk: DOC#{id} | sk: VER#{padded_version}
• Upload Session: pk: UPLOAD#{id} | sk: SESSION
• Idempotency Lock: pk: IDEMP#{client}#{key} | sk: REQUEST
  • בקרת מקביליות אופטימית: עדכונים מותנים (ConditionExpression: current_metadata_revision = :exp).
  • טרנזקציות אטומיות: TransactWriteItems מאחד עדכון מצביע, רשומת גרסה ונעילת Idempotency.
  • זרימת אירועי CDC: אירועי DynamoDB Streams נלכדים לעיבוד אסינכרוני במורד הצינור.

Amazon OpenSearch Serverless (AOSS)

OLAP / Read Projection

משמש אך ורק כאינדקס חיפוש נגזר (documents-v1) לסינונים מרובי-שדות ודפדוף יעיל.

Search Capabilities:
• Exact keyword filtering (document_class, branch_code, status)
• Numeric range queries (loan_amount_minor_units)
• ISO 8601 Date ranges (signed_date, created_at)
• Stateless Cursor Pagination via search_after
  • אפס ניהול קלאסטרים: מתרחב ומתכווץ אוטומטית לפי יחידות OCU.
  • בידוד תקלות: גם בעת השבתת אינדקס החיפוש, העלאות, עדכוני מטא-דאטה והורדות ממשיכים לפעול ב-100%.
  • אבטחת IAM SigV4: אימות והרשאות ישירות מול AWS IAM ללא סיסמאות סטטיות.
מדוע הפרדת CQRS היא דרישת חובה בארכיטקטורת Enterprise מודרנית?
1. בידוד משטח פגיעה (Blast Radius): שאילתות חיפוש כבדות או בנייה מחדש של אינדקס אינן פוגעות בביצועי הקליטה הטרנזקציונית או ב-SLA.
2. שחזור ותיקון עצמי (Self-Healing): היות ו-S3 ו-DynamoDB הם מקורות האמת הבלעדיים, ניתן למחוק ולבנות מחדש את אינדקס החיפוש מאנוטציות S3 בכל עת.
3. אופטימיזציית עלויות וסילום: תשלום לפי נפח השאילתות בפועל ללא צורך בהחזקת קלאסטרים ייעודיים יקרים 24/7.

קטלוג שירותי AWS מנוהלים והצדקה ארכיטקטונית

ההיגיון ההנדסי והבקרות המאובטחות מאחורי כל אבן בניין במערכת

קטלוג שירותי AWS
שירות AWS תפקיד בארכיטקטורה מדוע נבחר? (הצדקה ארכיטקטונית) בקרות אבטחה וממשל
Amazon API Gateway שער כניסה וניתוב REST ציבורי שער Serverless מנוהל לחלוטין; תמיכה ב-Cognito JWT Authorizer; הגבלת קצב (1,000 RPS עם Burst ל-2,000); העברת תוכן בינארי (*/*). TLS 1.2+, מוכן ל-AWS WAF, אימות JWT.
AWS Lambda מנוע חישוב מיקרו-שירותים תשלום לפי מילישניות ריצה; אפס תחזוקת שרתים; סקיילינג אוטומטי ב-Multi-AZ; זמני תגובה של תת-שנייה עם Node.js 20.x TypeScript. תפקיד IAM Execution Role ייעודי לכל פונקציה (Least Privilege).
Amazon S3 אחסון קבצים ואנוטציות מטא-דאטה עמידות של 11 תשיעיות (11 9s); ניהול גרסאות מובנה; הנפקת כתובות Presigned URL ישירות לעקיפת צווארי בקבוק במחשוב. הצפנת SSE-KMS, חסימת גישה ציבורית, Deny למחיקת גרסאות.
Amazon DynamoDB שכבת בקרה ונעילות (Control Plane) השהיה של מילישניות בודדות בכל עומס; טרנזקציות אטומיות (TransactWriteItems); עדכונים מותנים ל-OCC; זרימת אירועי CDC. הצפנת KMS, גיבוי רציף (PITR), בקרת גישה מדויקת ב-IAM.
Amazon OpenSearch Serverless היטל חיפוש ושאילתות עסקיות חיפוש טקסט מלא ומסננים מרובי-שדות ללא צורך בניהול גודל קלאסטר או Shards; הרחבת יחידות OCU אוטומטית; אימות IAM SigV4. מדיניות הצפנה ואבטחת רשת ב-AOSS Security Policies.
Amazon SQS & DLQ חיץ וצימוד אסינכרוני ספיגת עומסים פתאומיים בין DynamoDB Streams ל-OpenSearch; לכידת הודעות תקולות ב-doc-platform-mvp-index-dlq לאחר 3 ניסיונות. הצפנת תור באמצעות KMS CMK, התראות CloudWatch Alarms.
AWS Cognito ספריית זהויות וניהול תפקידי RBAC ספריית זהויות מנוהלת התומכת ב-OAuth 2.0 / OIDC; הנפקת טוקני JWT קריפטוגרפיים; מיפוי קבוצות משתמשים לתפקידים (Reader, Writer, Editor, Admin). אימות JWKS, אכיפת מדיניות סיסמאות קפדנית.
AWS KMS ליבת הצפנה ארגונית מרכזית מפתח מנוהל לקוח (alias/doc-platform-mvp) עם רוטציה אוטומטית שנתית המצפין את S3, DynamoDB, SQS ו-CloudWatch. מגובה בחומרת HSM מאושרת בתקן FIPS 140-2 Level 3.
Amazon CloudWatch & Trail ניטור, לוגים ותיעוד ביקורת לוגים מבניים בפורמט JSON, התראות עומק בתורי DLQ, התראות שגיאות 5xx, ותיעוד CloudTrail מקיף שאינו ניתן להכחשה. הצפנת Log Groups ב-KMS, טשטוש אוטומטי של שדות רגישים.

זרימת אירועים אסינכרונית וצינור עיבוד בעל תיקון עצמי

אינדוקס מנותק, תיעוד ביקורת S3 אוטומטי ובידוד תקלות באמצעות Dead-Letter Queue

הנדסת אירועים (CDC) וחוסן
שלבי ביצוע צינור האירועים האסינכרוני
1. ביצוע שינוי ב-DynamoDB: פעולת קליטה, עדכון מטא-דאטה או מחיקה רכה נרשמת ב-DynamoDB ומייצרת אוטומטית רשומת אירוע ב-DynamoDB Streams.
2. פונקציית Stream Processor: צורכת מקבצי אירועים (עד 10 רשומות) ומבצעת שתי משימות במקביל:
  • כותבת תיעוד ביקורת JSON בלתי מחיק ל-s3://audit-bucket/audit/{date}/{doc_id}_{event_id}.json.
  • משדרת הודעת אינדוקס לתור ה-Amazon SQS Indexing Queue.
3. פונקציית SQS Indexer: מעבדת מקבצי הודעות (עד 5), קוראת את אנוטציית ה-S3 המוסמכת, ומעדכנת/מוחקת את ההיטל ב-OpenSearch Serverless.
4. תור שגיאות (DLQ) והתראות: במידה ו-OpenSearch אינו זמין זמנית, SQS מנסה שוב 3 פעמים ולאחר מכן מנתב את ההודעה ל-doc-platform-mvp-index-dlq ומפעיל התראת CloudWatch.

גלריית תרשימי רצף ו-API
POST /v1/documents קליטת קובץ ישירה ב-Inline (≤ 4 MiB)
POST /v1/documents/uploads אתחול סשן העלאה ישירה (> 4 MiB)

דגשי ביצוע וגבולות סמכות

העלאה ישירה לקבצים בינאריים עד 4MB. מוודאת SHA-256 ומעטפת JSON Schema, כותבת את הקובץ ואת אנוטציית ה-JSON המוסמכת ל-Amazon S3, ומבצעת טרנזקציית DynamoDB TransactWriteItems אטומית ליצירת מצביע DOC#, רשומת היסטוריה VER#0000000001 ונעילת Idempotency.

ארכיטקטורת קליטה דו-ערוצית: Inline מול Direct S3

אופטימיזציית זמני קליטה ומניעת צווארי בקבוק של מגבלת 10MB ב-API Gateway

מסלולי קליטת קבצים
מסלול 1 העלאה ישירה ב-Inline (≤ 4 MiB)
בקשת HTTP יחידה המתאימה לחשבוניות סרוקות, קבלות, הסכמים קצרים ומסמכי PDF סטנדרטיים.
POST /v1/documents with binary body + headers:
  • Content-Type: application/pdf
  • X-Content-SHA256: {hex_hash}
  • X-Document-Metadata: {base64_json}

יתרונות: אפס תיאום מקדים; קליטה אטומית בבקשה אחת בלבד; תגובת 201 Created מיידית.

מסלול 2 העלאה ישירה ל-S3 באמצעות Presigned URL (> 4 MiB)
פרוטוקול דו-שלבי המיועד לתיקי הלוואה כבדים, תיקי משכנתא וסריקות מרובות עמודים.
Step 1: POST /v1/documents/uploads (אתחול סשן וקבלת Presigned S3 URL ל-15 דק')
Step 2: PUT {presigned_url} (הזרמת הקובץ הבינארי ישירות ל-S3)
Step 3: POST /v1/uploads/{id}/complete (אימות אובייקט והפעלת מצביע)

יתרונות: עוקף את מגבלת 10MB ב-API Gateway ואת זיכרון ה-Lambda; מזרים במהירות קו מלאה ישירות ל-S3.

פרופיל ביצועים וסילום בקליטה

השהיית העלאה ב-Inline:
~120ms עד 250ms זמן תגובה כולל מקצה-לקצה, כולל טרנזקציית DynamoDB וכתיבת S3 PutObject.
רוחב פס בהעלאה ישירה ל-S3:
תמיכה בקבצים עד 5GB ב-Single-PUT או Multipart Upload ללא שום לחץ זיכרון על שכבת ה-Compute.
פקיעת תוקף סשנים:
סשנים של העלאה ישירה שלא הושלמו נמחקים אוטומטית באמצעות DynamoDB TTL לאחר 24 שעות.

ממשל וניהול מקביליות
בקרת מקביליות אופטימית (Optimistic Concurrency Control)

בעת עדכון מטא-דאטה, הלקוח חייב להעביר את מספר הרוויזיה הנוכחי שבידיו דרך expected_metadata_revision:

PATCH /v1/documents/{id}/metadata
{
  "expected_metadata_revision": 1,
  "changes": { "branch_code": "TLV-05" }
}
  • שמירה מותנית ב-DynamoDB: מריץ ConditionExpression: current_metadata_revision = :expRev.
  • פתרון קונפליקטים: במידה ומשתמש אחר ערך את המסמך קודם לכן, הבקשה נדחית ב-409 METADATA_CONFLICT עם מספר הרוויזיה העדכני.
התפתחות תבניות סכמת JSON (Schema Evolution)

אימות קפדני בתקן JSON Schema Draft-07 עם additionalProperties: false:

1. מודל GitOps בזמן בנייה (Phase 1):
סכמות מנוהלות ב-Git (schemas/loan_agreement-v1.json) ומקומפלות לזיכרון ה-Lambda ב-Cold Start באמצעות Ajv. אפס השהיות רשת.
2. רגיסטרי סכמות דינמי בזמן ריצה (Phase 2):
טבלת DynamoDB ייעודית (doc-platform-schemas) המאפשרת למנהלי מערכת להוסיף סכמות בזמן אמת ללא צורך בפריסת קוד מחדש.

ניטור מלא, מעקב מבוזר ושקיפות ביקורת (Observability & Tracing)

תיעוד מובנה ב-CloudWatch, מעקב חוצה-מערכות באמצעות Correlation ID, התראות אוטומטיות ויומן ביקורת בלתי-הפיך ב-S3

ניטור, בקרה ורגולציה
לוגים מובנים בפורמט JSON
כל פונקציות ה-Lambda משתמשות ברכיב Logger מרכזי הפולט JSON מובנה הכולל correlationId, documentId, userId, version ו-route.
  • מיסוך אוטומטי של PII, טוקנים ונתונים רגישים
  • אינדוקס וחיפוש מהיר ב-CloudWatch Logs Insights
מעקב מבוזר (Distributed Tracing)
כל קריאת REST מוחתמת ב-API Gateway ב-requestId ייחודי המועבר כ-correlationId לאורך כל שרשרת העיבוד: DynamoDB Streams ← SQS ← Indexer ← OpenSearch.
  • מיפוי תלויות מלא באמצעות AWS X-Ray ו-ServiceLens
  • מעקב סיבתי מדויק אחר אירועים אסינכרוניים
התראות ולוח מחוונים מרכזי
ה-Stack הייעודי ObservabilityStack פורס התראות CloudWatch אוטומטיות ולוח בקרה תפעולי מלא (doc-platform-mvp-dashboard).
  • התרעת DLQ מנותק (≥ 1 הודעות) לכשלי אינדוקס
  • התרעת שגיאות שרת (≥ 5 שגיאות 5xx ב-5 דקות)

תיוג גלובלי אוטומטי לכל המשאבים הפרוסים (S3, DynamoDB, Lambdas, SQS, API Gateway, CloudFront, OpenSearch) לניהול ציי ענן ובקרת עלויות.

שאילתות דיאגנוסטיקה ואיתור משאבים ב-AWS

שאילתות אינטראקטיביות בזמן אמת לרוחב לוגי המערכת וחיפוש ב-AWS Resource Groups:

# 1. מעקב אחר בקשה ספציפית לפי Correlation ID
fields @timestamp, level, message, documentId, userId
| filter correlationId = "c8f94d21-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
| sort @timestamp asc
# 2. מעקב היסטוריית פעולות לפי Document ID
fields @timestamp, level, message, version, userId
| filter documentId = "doc-uuid-here"
| sort @timestamp desc
# 3. איתור חריגות ושגיאות מערכת גלובליות
fields @timestamp, @logStream, level, message, error.message
| filter level = "ERROR" | sort @timestamp desc | limit 50
# 4. איתור מיידי של כלל משאבי המערכת לפי תגית פרויקט
aws resourcegroupstaggingapi get-resources
  --tag-filters Key=Project,Values=aws-document-management-platform

סיכום אסטרטגי ותובנות ארכיטקטורה

החלטות ארכיטקטוניות מרכזיות, חיסכון בעלויות בעלות כוללת (TCO) ומוכנות לעתיד

סיכום מנהלים
1. אפס עלויות במצב סרק (Zero Idle TCO)
על ידי הימנעות מהחזקת שרתי EC2, מכולות ECS או קלאסטרים קבועים של OpenSearch הפועלים 24/7, העלות התפעולית מתאימה במדויק לנפח הפעילות. סביבות פיתוח ובדיקות ללא תנועה עולות $0.
2. עמידות מקסימלית ועמידה ב-WORM
עמידות של 11 תשיעיות (11 9s) ב-Amazon S3 בשילוב ניהול גרסאות מובנה וחסימה מוחלטת של s3:DeleteObjectVersion ב-IAM מעניקים עמידה רגולטורית מוכחת.
3. בידוד תקלות מלא (Blast Radius Isolation)
ארכיטקטורת CQRS מנותקת מבטיחה שבנייה מחדש של אינדקס, עומסי חיפוש או תקלות זמניות ב-OpenSearch לעולם לא ישפיעו על הורדת מסמכים, קליטת קבצים או עדכוני מטא-דאטה.

תקציר תיעוד החלטות ארכיטקטורה (ADR Summary)

תחום החלטה ארכיטקטורה שנבחרה חלופות שנפסלו הנימוק הארכיטקטוני המכריע
אחסון מטא-דאטה S3 Native Object Annotations כותרות S3 Metadata (מגבלת 2KB), קובצי Sidecar נפרדים, עמודות JSONB במסד נתונים יחסי מבטל את מגבלת 2KB; מונע פיצול קבצי Sidecar; מאפשר עריכת מטא-דאטה ללא שכפול קובץ בינארי; מוכן לאנליטיקת Apache Iceberg.
שכבת בקרה (Control Plane) DynamoDB Single-Table Design Amazon Aurora PostgreSQL, MongoDB Atlas השהיה חד-ספרתית של מילישניות בכל עומס; זרימת אירועי CDC מובנית; טרנזקציות רב-פריטיות אטומיות ללא מגבלות Connection Pool.
שכבת חיפוש (Search Tier) OpenSearch Serverless (AOSS) קלאסטרים מנוהלים של OpenSearch, שאילתות DynamoDB GSI אפס ניהול/עדכון גרסאות קלאסטר; סקיילינג דינמי של יחידות OCU; תמיכה בשאילתות טווח ומסננים מורכבים שאינם נתמכים במפתחות DynamoDB.
מנוע חישוב (Compute Engine) AWS Lambda (Node.js 20.x TS) ECS Fargate Containers, EKS Kubernetes פשטות תפעולית אמיתית של Serverless; סקיילינג בתת-שנייה; מיקרו-פרימטרים של הרשאות IAM הדוקות ביותר.
